The core calls only these five functions. They are the swap point.

Assert form (shapes)Example
A.prop OP B.prop [* k]body.height >= body.width * 1.5

[all] A inside Ball window inside body
no-overlap A B …no-overlap house tower tree
count(A,B) OP ncount(house,tower,tree) >= 2

Props: top, bottom, left, right, width, height, cx, cy. == has a tolerance of 4 px. An assert on a missing optional part is skipped.

Add a patternTo an existing domain›
  1. Copy a pattern of the same kind in domains/<domain>/patterns/. Name the file <id>.md.
  2. Write use_when, do_not_use_when, variants, parts, params and asserts.
  3. Add the new id to parts of its parent, and to related of the near patterns.
  4. Run node core/graph/build.mjs <domain>. Fix each error.
  5. Add a good and a bad fixture to fixtures/ and expect.yaml. Run the self-test.
  6. Add 1 near-miss hand case. The generator adds the other cases from phrase.
  7. Run --mode dev --only <case ids>.
Add a caseHand cases for what the generator cannot make›
  1. Add an entry to domains/<domain>/cases/*.yaml: id, tags, request, expect.
  2. Use the tag near-miss or no-fit. The sample and the report use these tags.
  3. For a near-miss case, make sure that the plain words point to the wrong pattern and only the rule gives the correct one.
  4. Run --dry to see it in the case list.
Add an ablationProve that an eval tests a part›
  1. In SKILL.md, put the text between <!-- ablate:name --> and <!-- /ablate -->. For a pattern field, add a rule to prepareSandbox in core/eval/agent.mjs.
  2. Run the cases that must fail with --ablate name.
  3. If the score does not go down, the cases do not test that part. Write harder cases.
Add a domain packFor example ui or code›
  1. Copy domains/shapes/ to domains/<name>/.
  2. Set the output file in domain.yaml.
  3. Write the subject rules in instructions.md. Tell the agent how to mark each pattern in the output, as data-p does for SVG.
  4. Write the five adapter functions.
  5. Write the patterns, the fixtures and the hand cases. Run the build and the self-test.
  6. Run --mode smoke, then --mode dev.
Principle

Code owns the loop. The model owns only the judgment.

Today the agent follows a workflow that it reads. Next, C# code runs the workflow and calls the model for one decision at a time.

Each call has a JSON schema, so the answer is typed. The code writes the trace, so the trace is exact. The engine can run with a scripted judge, so the tests need no model.

Key types

The two interfaces

IDomainAdapter is the swap point for a subject. IJudge is the only place that calls a model.

public sealed record Pattern(
    string Id, Kind Kind, int Level, Status Status,
    IReadOnlyList<string> UseWhen,
    IReadOnlyList<Exclusion> DoNotUseWhen,
    IReadOnlyList<Variant> Variants,
    IReadOnlyList<PartSpec> Parts,
    IReadOnlyDictionary<string, ParamDef> Params,
    IReadOnlyList<string> Asserts);

// the swap point for a subject
public interface IDomainAdapter
{
    ParsedOutput Parse(string text);
    Problems Lint(ParsedOutput output);
    AssertResults Assert(Node node, Asserts asserts);
    Problems CheckLeaf(Node node, Pattern leaf);
    string? ReadParam(Node node, string key,
                      ParamDef def);
    string Assemble(BuiltNode root); // new
}

// the only model boundary
public interface IJudge
{
    Task<Selection> Select(string request,
        IReadOnlyList<IndexRow> candidates);
    Task<bool[]> Exclude(string request, Pattern p);
    Task<VariantChoice> ChooseVariant(
        string request, Pattern p);
    Task<ChildRequest[]> PlanChildren(
        string request, Pattern group);
    Task<string> Compose(NodeContext ctx,
        Problems lastFailures);
}

Spike 2 · modular harness

One file for each role, step, rubric and output shape

A harness is the set of agent files that the sandbox gets. The cases, graders and model stay the same, so two harnesses can be compared. Select one with --harness monolith|modular.

5skills: 1 router, 4 steps
2agents: composer, verifier
1rubric, separate from its agent
4templates for fixed output shapes
5pe commands for agent and system
The chain

Router, step skills, agents

Orange: model. Green: a command that the agent runs and that the system can also run. Each step writes a file; the next step reads it.

No pattern fits

Skill pattern-nofit: nearest, deltas, pe scaffold from the template, steps/nofit.json, then plan.json.

Gate (system side, --gate)

After the agent stops, the runner runs the same verify. On a failure, it starts the agent once more with the failures.
