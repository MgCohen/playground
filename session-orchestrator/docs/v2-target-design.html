V2 Target Design

Each page and each list of the app is a view of one query of the event stream. A composer joins the view template, the content template of each kind and the query result into one view model, off the UI thread. The page renders it only with design system components. One navigator owns where the user is, and each motion is a step of a state transition. The diagnosis is on the V2 Visual Restart page.

Data goes one way: down as parameters. Input goes the other way: up as events into a state machine, which posts to the store. Each state change is a trace event.

Open questions

D1Rename the kind file to content.json?Recommendation: yes. Default: yes
Context

Today templates/<kind>/view.json holds the content of a kind. The new catalog has view templates too. One word with two meanings breaks rule 2 of the writing rules.

Options
  • A: rename to content.json.
  • B: keep view.json, and call the new files lens.json.
Recommend

A. The kind file holds content; the view file holds a query and a layout.

D2Own design system or a component library?Recommendation: own, on CSS tokens. Default: own
Context

The prior-art research found that Blazor libraries such as MudBlazor have no motion system, and their look is not ours. Our look and motion are approved.

Options
  • A: own components on our tokens (tab 4).
  • B: Fluent UI Blazor, themed.
  • C: MudBlazor, themed.
Recommend

A. The catalog has about 30 small components. A library adds a second style system to override (P5).

D3Thin WinForms host for the tray?Recommendation: option A of tab 5. Default: A
Context

Only WebView2 composition is proven for a transparent, shaped window. WinUI 3 and MAUI are not proven for it.

Options
  • A: thin WinForms host with IHostWindow.
  • A + spike: also try WinUI 3 in step 3.
Recommend

A. Make the host small first; change the host later only if the spike shows a gain.

D4New projects next to the old app?Recommendation: yes, in the same solution. Default: yes
Context

A rewrite in place breaks the app for a long time. New projects let the old app run, and each slice can compare with it.

Options
  • A: new projects in Orchestrator.slnx (tab 1).
  • B: rewrite the pages in place.
Recommend

A. The supervisor, the store and the API stay as they are.

D5How do card rules test the fields?Recommendation: small JSON tests, no script. Default: JSON tests
Context

Ui.Classify tests fields: two options yes and no, a default, the needs. The rules must be data (P11).

Options
  • A: JSON tests: exists, is, equals, count (tab 2, V5).
  • B: an expression language, for example JsonLogic.
Recommend

A. Four tests cover the 8 variants of today. A schema can check them.

D6Do overlays change the URL?Recommendation: no; overlays live only in the stack. Default: no
Context

Sheets and the speed dial become stack entries (tab 3). The browser Back key must close them. A URL for each overlay makes deep links to a half-done answer.

Options
  • A: no URL change; the navigator catches the browser Back for an open overlay.
  • B: a #sheet fragment for each overlay.
Recommend

A. A link opens a page, never a half-open sheet. The tray has no address bar.

One navigator, one stack

Each "-ing" state ends only on an end event: a motion end from the page, or a window event from the host. Input waits for a rest state, so a press in Opening waits for Open (I19).

One motion system

Each motion is the look of one row of a state machine. The row names a motion step; the player runs it and fires the end event. No motion starts outside a row (P12).

Guidelines and names

  • The design system is a "Design System" artifact: tokens, components with live previews, and the rule of use of each part.
  • One C# file lists each class, state and motion name. A build step writes it as CSS and JS constants, so the three languages share one source (P2).
  • A test reads the CSS and fails on a literal outside tokens, on an unknown var() name, and on a rule with no markup.

Option A: the thin host

// The only native contract. The tray state machine calls it.
public interface IHostWindow
{
    Task Show(Place place);        // ends on the "shown" window event
    Task Hide();                   // ends on "hidden"
    void UseSize(PageSize size);   // from its own root only (P8, Places G5)
    event Action<HostInput> Input; // click, drag, key: to the trace
}
  • One class for both windows: DPI, display change and exit are written once (Places G8).
  • No GDI+ drawing: the ball and the badge are page content (V5 lesson).
  • Place rules are pure functions with unit tests (Places G7).
