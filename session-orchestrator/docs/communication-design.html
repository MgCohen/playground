Session orchestrator · A1 communication design

Orchestrator Messages

Each message is one event of one kind, with one template, and goes through one entry point, Messages.Post. Delivery to a session uses one inbox format and one acknowledge record. The user inbox is a query of the event stream: open events that need the user, with no reply.

Inbox file

// sessions/<id>/inbox/<event id>.json — one file for each receiver of a message
{ "message": "<event id>", "kind": "answer", "from": "user", "thread": "toolu_01RAQ",
  "text": "Answer to decision toolu_01RAQ (Which color …?): GREEN" }

The name is the event id, so the names sort by time. The text is the render for this receiver, made at queue time.

Delivery rules

  1. Only the lease holder delivers. Holder live: the plugin. Any other holder: a supervisor turn.
  2. Deliver in the order of the inbox names. Answers use the same inbox. There is no second path.
  3. Skip an item that has a delivered/<message>.json record.
  4. A supervisor turn joins the items with ---. The plugin submits one item for each turn.
  5. Delivery is at least once. After a crash, an item can arrive two times. The text holds the message id, so the model can see a repeat.
  6. If a submit is refused (stop latch), write delivery.blocked one time. Try again each 3 s. Write delivery.resumed after the next good submit.
  7. Write the message event first, then the state file, then the inbox file.
