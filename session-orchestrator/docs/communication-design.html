Session orchestrator · A1 communication design

Orchestrator Messages

All communication goes through one event stream. A sender posts a body file to the store and an envelope to the stream. Each party gets a notification for each envelope to its address, then queries and reads what it needs. Inbox, queue, relays and defaults are reactors on the stream.

There is one transport. A party never writes a file of another party. Each feature (inbox, queue, relay, default, docs check) is a reactor: a subscription filter, a reaction, and new posts.

Permissions are a layer above these primitives. This page does not design them.

Four rules

  1. Each communication is one post: one body file in the store and one envelope in the stream.
  2. Each party is always subscribed to the envelopes with to = its address. Other filters are optional.
  3. A receiver decides what to do. It reads the body only when it needs the content.
  4. A nudge carries no content. It only makes the receiver look at the stream sooner.

Nudge: a direct ping, not a message

Receiver stateThe nudge doesTransport
Subscriber process runsWakes it before the next pollnudges/<party> touch, file watcher; SSE for the UI

Session not liveStarts a supervisor turn nowSupervisor tick
  1. A nudge never carries content. The receiver queries from its cursor and reads what it needs.
  2. A nudge is best effort. It can be lost or arrive two times. The poll still delivers each envelope.
  3. A post does not need a nudge. A sender nudges only when the receiver must act soon.
  4. The stream records no nudge. The receiver records what it does as usual.

Store layout

store/
  events/<day>/<id>.json        // envelopes, append only, one file each
  bodies/<day>/<id>.json        // bodies, write once
  subscriptions/<party>/<name>.json  // { filter, cursor } of one subscriber
  nudges/<party>                // empty file; its time stamp is the nudge
  sessions/<id>/                // lifecycle files of stream B: lease, heartbeat, meta

The stream has no other communication files. inbox/, answers/, delivered/, reviews/, report.json, update.json, cursor.txt and forwarded* are queries. A reactor can keep a cache, if it can make the cache again from the stream.

FieldUse
toThe address that gets the notification. One address for each envelope
bodyThe path of the body. Two envelopes can point to one body
threadGroups the envelopes of one conversation
needsMarks an envelope that waits for an act of the receiver
refs.replyThe envelope that this envelope answers. Closes it
refs.ofA forward or an acknowledge: the original envelope
refs.viaThe relay that typed the words of the user

Post, notify and acknowledge rules

  1. Post writes the body first, then the envelope. The envelope is the commit point. A body with no envelope is ignored.
  2. Envelopes and bodies never change. A correction is a new post.
  3. A forward is a new envelope with a new to, the same body and refs.of.
  4. Notify is at least once, in id order. A subscriber moves its own cursor after it reacts.
  5. A subscriber that was down reads from its cursor at start. No notification is lost.
  6. A receiver that acts posts the act: a reply with refs.reply, or an ack with refs.of.
  7. The subscription cursor is private. Other parties see only the posted acts.
