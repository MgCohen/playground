Tray Motion Guide

session-orchestrator · motion pipeline (R1) · 2026-11-20

The rule. CSS owns each motion: its time, its curve, its target and what ends it. C# only sets a state class, waits for the end of the step, and orders the steps. C# calls JS only through a command record.

The one exception. C# owns the window steps of the tray (a window shows or hides), because C# controls the windows. See the tab "Tray and deck".

Read this guide before you add, change or use a motion. The design of the pipeline is in the motion pipeline (R1) plan.

One motion step

C# component

  1. Set the state class (is-open, out-r).
  2. Send MotionWait(step).
  3. Read the result, then do the next step.

CSS rules

  1. The rule of the class plays the motion with a token: var(--t-grow).
  2. The step rule names what ends the step: --motion-wait: clip-path.

JS motion.js

  1. orchMotion.wait finds the target by data-motion.
  2. It waits for the motions in --motion-wait.
  3. It returns { by, ms }.
// TrayStage.razor: the grow
Set(TrayPhase.Open);                                                                // 1. state class is-open
await Commands.SendAsync(new MotionWait(MotionSteps.Grow.Target, WaitMode.Step), default);  // 2. wait for the step

/* tray.css */
[data-motion~="grow"] { --motion-wait: clip-path; } /* G1 · tray */

<!-- TrayStage.razor -->
<div class="tray-panel" data-motion="grow">

Recipes

Open the recipe for your task.

Change a time or a curve a token in motion.css
  1. Change the token in the :root block of motion.css. Do not write a time in a view file: Components/, wwwroot/ and the tray windows (TrayWindow, BadgeWindow, WidgetWindow, ClearHost). TrayFlow is in Components/, so the rule applies to it.
  2. If the motion has no token, add one with the name --t-<thing>. Use var(--t-<thing>) in the rule.
  3. If the token is a duration, add it with 1ms to the reduced motion block. The test Reduced_motion_sets_each_duration_token_to_1ms finds a missing one.
  4. If the token is a dwell time (how long a thing shows) or a limit, do not add it to the reduced block. Add its name to Kept in MotionArchitectureTests.cs. Kept has --t-undo, --t-peek-show, --t-limit, --t-vt-start, --t-vt-render, --t-frame-limit and --t-window-gap.
Add a motion that nothing waits for hover, press, first show, ring draw
  1. Write the rule in motion.css (or tray.css) with tokens. Add a comment with the spec ID of docs/motion-design.html.
  2. Set the state class in the .razor file.
  3. Add no C# wait and no registry row.
Add a step that C# waits for the next action comes after the motion

Use this when a window hides, an act runs or a block goes away after the motion.

  1. Add a row to MotionSteps.cs, and add it to All. This is also the file for a step of the tray.
  2. Mark the target in the .razor file. One element can have more than one step name: data-motion="badge-in badge-out".
  3. Write the step rule, with the spec ID as a comment on the same line. The spec ID must be in docs/motion-design.html. If the motion has no spec, add it to that page first. --motion-wait names the transition properties or the animation names that end the step. With no value, the step waits for each finite motion of the target and its children (settle).
  4. In C#, set the class, render, then wait. Inject ICommandSender Commands. Set the same class as State of the row; use MotionSteps.X.State where you can.
  5. Run the unit tests. Registry_matches_motion_css fails if the row, the mark and the rule do not agree, or if the spec ID is not in motion-design.html. Each_state_class_has_a_rule fails if no style sheet has the class of State.
  6. Run the self-test. steps-traced checks each row of All. If the self-test does not run your step, add it to the self-test, or add it with its reason to the list notTraced in SelfTest.cs.
// MotionSteps.cs
public static readonly MotionStep SheetOut = new("sheet-out", "is-leaving");

<!-- the component -->
<div class="sheet" data-motion="sheet-out">

/* motion.css */
[data-motion~="sheet-out"] { --motion-wait: transform opacity; } /* M5 */

// the component
phase = "is-leaving";
StateHasChanged();
await Commands.SendAsync(new MotionWait(MotionSteps.SheetOut.Target, WaitMode.Step), default);
// with an ElementReference: new MotionWait(root, WaitMode.Step)

Add a window step a tray window shows or hides in a new phase
  1. Add the phase to TrayPhase in src/Orchestrator.Web/IWidgetWindow.cs.
  2. Add a row to WindowSteps.cs (name, phase, window event), and add it to All.
  3. In src/Orchestrator.Tray/WidgetWindow.cs, Enter: show or hide the windows for the phase, and set LastEvent ("shown", "hidden", "activated").
  4. In TrayFlow, call await Window(TrayPhase.X) for the window step and await Page(() => page.Step()) for each page step.
  5. Add the step name to windowSteps of the check window-steps in SelfTest.cs, and to the order test in TrayFlowTests.cs.
Add a scenario a recording that proves a change
  1. Add one entry to the list Scenarios in src/Orchestrator.Tray/SelfTest.Scenarios.cs: a name and the steps. Write each step to the log with step("...").
  2. Click with window messages (Press), so the pointer of the user does not move.
  3. Keep the scenario between 5 and 15 s. Give the recording 2 s more than the scenario.
  4. If the name ends with -reduced, the scenario runs with reduced motion.

The wait command

MotionWait(target, mode, arg). The target is a selector, an ElementReference, or null (frames and time).

ModeArgEnds when
StepnoneThe motions in --motion-wait of the target end (settle if empty). Use it for each registry step
SettlenoneEach finite motion of the target and its children ends
Property"clip-path" or "clip-path scale"These transitions or animations of the target and its children end
Time"--t-peek-show"The time of the token passes. Use it only for a dwell token (how long a thing shows), not to wait for a motion. With reduced motion a dwell token keeps its value, so the wait keeps its full time
Event"frames:2" or a DOM event namen display frames pass, or the event comes

Each wait ends at the latest after --t-limit (--t-frame-limit for frames). If the wait finds no motion, it looks again for 2 frames, because the class can come in the render after the call.

The result

ByMeaningDo
endThe motion endedGo on
cancelThe browser stopped the motion: the state changedGo on. A newer step owns the element
limitThe limit ended the waitDefect The trace has a "wait at limit" line. Examine --motion-wait
hiddenThe page is hidden; nothing movesGo on
missingNo targetDefect Examine data-motion and the selector

A JS error comes back as waited.Error (code js.failed or js.canceled), not as an exception. The trace has it.

NameWhere it comes fromMeaning
By == "cancel"The browserThe motion stopped, because the class changed during the wait. The wait completed
Error.Code == "js.canceled"C#A newer call with the same Key stopped this call. The wait did not complete

Newer call wins

Give the command a Key. A newer call with the same key cancels the older call, which ends with js.canceled. The key is any text; use the step name. The keys are separate for each page and each tray window.

var waited = await Commands.SendAsync(new MotionWait(page, WaitMode.Step) { Key = MotionSteps.TabIn.Name }, default);
if (waited.Error?.Code == JsErrors.Canceled) return;

Add a C# to JS call

This is for each call from C# to JS, not only for motion.

  1. Write a record. The JS name comes from the type: orch and the first word of the type is the object; the other words, joined in camelCase, are the function (MotionWaitAll → orchMotion.waitAll). The constructor parameters are the arguments, in order.
  2. Put it in a slice of its feature: Features/<Feature>/Slices/<Name>/<Record>.cs.
  3. Write the function in a script of src/Orchestrator.Web/wwwroot/. A new script file must load in Components/App.razor (web) and in src/Orchestrator.Tray/wwwroot/index.html (tray).
  4. Send it with Commands.SendAsync.
  5. Do not write a handler. One handler (JsCommandHandler<TResult>) runs all JS commands.
public sealed record SpeechFocus(string Id, bool Voice) : JsCommand<Unit>;      // orchSpeech.focus, no result
public sealed record MotionMs(string Token) : JsCommand<double>;               // orchMotion.ms, a result
public sealed record OldName(string X) : JsCommand<Unit>("orchLegacy.run");    // a name that is not from the type

// the script
window.orchSpeech = { focus: function (id, voice) { /* ... */ } };

// the component
await Commands.SendAsync(new SpeechFocus("sheet-text", true), default);

The tray windows

The tray has page steps (a page plays a motion) and window steps (a window shows or hides). C# owns the window steps, because C# controls the windows.

PartRule
Window stepA row of WindowSteps.cs: panel-show, panel-activate, badge-show, all-hide. TrayFlow runs it through Window(phase)
Page stepTrayFlow runs it through Page(...). The page waits for its motion
TraceEach window step with its event, its time and the window gap
RequestsOne runs at a time. A request during a run waits, and only the last one runs
ErrorsAn error goes to the fault log of the tray. The phase becomes the phase of the windows
Badge noticeOnly for a card that arrives while the tray is closed (hidden or at the badge), one time (TrayNotices)
window badge-show: shown in 35 ms, gap 0 ms
window panel-show: shown in 24 ms, gap 0 ms

The deck

swipe.js follows the pointer and clicks the act buttons. C# starts the throw and the tuck (the classes out-r, out-l, tuck), waits for the step deck-throw or deck-tuck, then does the act. Do not add a timer to swipe.js.

Check a change

  1. Run the unit tests: dotnet test --solution Orchestrator.slnx. Set GITHUB_TOKEN (gh auth token) before the first restore.
  2. Run the tray self-test: dotnet run --project src/Orchestrator.Tray -- --selftest <folder>. Add --reduced for reduced motion. The folder gets selftest.json (each check with Pass and its message), the pictures and exceptions.log. Only badge-hover-fits (I7) fails today.
  3. Record a scenario before and after the change. Do not use the computer during the recording, and close each dialog first: a window in front of the tray changes the frames.
  4. Read the trace in the log of the scenario.

Known limits

  • Umpire gives the finding UMP020301 for each JS command record: the VSA rule wants a handler in the slice. This is an Umpire gap. The test R1_folders_have_no_findings reads all of Plugins/ and Features/, and allows only this finding.
  • Pointer motion (a drag) stays in the script: C# cannot follow each frame.
  • A spring is a cubic-bezier. CSS has no physics.
  • The window gap has a reference token (--t-window-gap), but no code waits for it (I15).
