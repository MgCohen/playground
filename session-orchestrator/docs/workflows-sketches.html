Workflows Sketches

Sketches of the eight pages and components of the Workflows feature. Each tab has 2 or 3 variants in the 350 px widget frame, with sample data. The notes give the purpose, the difference between the variants, and the source of each part. Pick a variant for each item, or say the change. The spec of the feature is on the page Advanced Features, tab F2.

The three views

  • A · Graph. A read-only node graph. Forward edges go down. A loop goes back on the right side, with its condition in a small label. A skip goes on the left. Under the graph, the runs of this workflow as run rows.
  • B · Outline. One row for each step, in definition order. The next conditions are rows with an indent: "→" goes forward, "↺" goes back. Easy to read on a phone, and it shows each condition in full.
  • C · Fields. The fields of each step, as in workflow.json, in a readable form. The future editor (W-6) edits these same fields.

Recommendation: open in the Graph view on a wide screen, and in the Outline view on a phone. Remember the last pick of the user.

Variants

  • A · Sheet on the graph. The sheet slides up over the graph. The graph stays behind it with the selected node marked. Previous and next move through the steps without a close.
  • B · Own page. All fields in groups: executor, data, approval, next, comes from. The arrows in the header move to the previous and next step. More room for long instructions.

Recommendation: A on a phone, and a side panel beside the graph on a wide screen. The user keeps the shape of the workflow in view.

Notes

  • "Used" counts the runs and step runs of this step. It links to the Runs page with a filter.
  • "Comes from" is the list of steps whose next points here. It is a query of the definition.
  • The future editor (W-6) makes these fields a form. No drag on the graph.

Variants

  • A · Wait mode. The run waits for you. The wait card is first, with the item to review and the result of each act ("Change → Ask one question"). A step bar with pass counts replaces the graph. The last three step runs give the context.
  • B · Check mode, graph. The run does not wait for you. The ring shows the steps on the path to done. The graph shows the path in green, the current step in orange and the next step dashed. Then "why here", "what if", and the time split. The page bar has the control acts of B2.
  • C · Check mode, outline. The same facts as B, as one row for each step. The passes and the outputs fold under each step. It shows the time of each step, and who spent it.

Recommendation: A when the run waits for you. B on a wide screen and C on a phone in check mode. B and C are the same data, so a switch is cheap.

The chip fits inside a card or a bar. The number is the current step.

Variants

  • A · One line. A small ring, the goal, the workflow and the current step, and a state pill. The same height as a session row, so the two mix in one list.
  • B · Two lines. Adds a step bar and the wait. Better on the Runs page, where there is room.
  • C · Chip. A compact link for places with little room: a question card, the stream bar.

Recommendation: A everywhere in lists, C inside cards and bars. B only if the Runs page picks variant B.

Rules

  • A click on any part of the row opens the run page.
  • The pill uses the same colors as the session states: orange waits for you, blue runs, green done, red stopped.
  • The ring shows the steps on the path to done, not the passes.

Variants: the three kinds

  • A · Approval. The item to review, the open links, and what each verdict does. The verdict buttons are the review acts of today.
  • B · Pick. Many next steps are valid. Each option shows its condition. If the owner session already proposed one, it has a mark.
  • C · Stuck. No next step is valid. The card shows what each step needs. "Force a step" is the new runner act of B2 (P-G12). This replaces the stuck question of C3-F2.

Recommendation: all three ship. They share one layout: kind pill, source line, lead, context, options with conditions, acts.
