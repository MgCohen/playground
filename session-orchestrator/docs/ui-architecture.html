Guide

  1. A new card type: add its group, label and two actions in Ui.cs. The deck, the ring and the badge read it.
  2. A new page level: put [PageDepth] on the page. The motion host selects the move.
  3. A new time: add a token to motion.css. If it is a duration, add it to the reduced motion rule with 1 ms.
  4. A new motion step: add a row to MotionSteps, a data-motion target and a step rule with a spec ID. Follow docs/motion-guide.html.
  5. A new tray size: add a token to tray.css and read it in orchTray.sizes(). Do not add a size constant to a window.

Each window step writes one trace line: its event, its time and the gap from the last page step. A wrong event is a warning. A wait that ends by its limit is a warning (WaitLimitHook).

Guide

  1. Read the motion guide first (docs/motion-guide.html).
  2. One request runs at a time (TrayFlow.Request). A request during a run waits. Only the last one runs. A notice waits for the end of the run (H4).
  3. A new step inside one window: add a MotionStep to MotionSteps. Put data-motion on the element. Give it a --motion-wait rule in tray.css.
  4. Wait with Commands.Must(new MotionWait(step.Target, WaitMode.Step)). Use the time tokens of motion.css.
  5. A new step between the windows: call Window(phase) in TrayFlow after the page step. Add a WindowStep with its expected event.
  6. Do not use Task.Delay or a time literal. MotionArchitectureTests and MotionRegistryTests fail on them.

The CSS contractCSSdata-motion, --motion-wait, --t-* tokens
  • data-motion="name" on the element that moves (more names with spaces).
  • --motion-wait in the step rule: the property or animation names. No value: the wait settles.
  • Each time is a --t-* token of motion.css. Reduced motion sets each duration token to 1 ms.
  • Shared rules are in motion.css. Rules for one host are in the sheet of that host (tray.css).

API

recordMotionStep(Name, States)one step of the registry: name, state classes, target
  • Name: the step name. It is the data-motion value.
  • States: the state classes that start the motion. State is the first one.
  • Target: the selector [data-motion~="Name"].
commandMotionWait(Target, Mode, Arg)wait for the end of a motion → WaitResult
  • Target: an ElementReference or a selector. Not used for Frames.
  • Mode: Step (the CSS rule names the wait), Property, Settle, Frames.
  • Arg: for Property the property or animation names ("clip-path scale"); for Frames the number of frames.
  • Key (init): a newer call with the same key cancels the older one.
recordWaitResult(By, Ms)how the wait ended, and its time
  • end: the motions ended. cancel: the browser stopped a motion. hidden: the page is hidden.
  • limit, none, missing: AtLimit is true, and the trace gets a warning.
  • Ms: the time of the wait.
methodSendAsync(command, ct)ICommandSender: send a command, get a Result

Gives a Result<T>. An error is in the result, and the trace has it. Use it in components.

methodMust(command)FlowCommands: send; an error throws a flow fault

For a flow step (the tray stage, the badge). An error throws, and TrayFlow writes a fault. A cancel does not throw.

commandMotionBegin(Kind)start a view transition: "push" or "back"

Sent by MotionHost. It returns when the browser has the picture of the old page, not at the end (G2).

commandMotionDot(Nav)move the nav dot to the current tab

Sent by AppBar. No wait.

commandMotionMs(Token)the value of a token in ms

Used through MotionTimes.Of, for example --t-undo and --t-peek-show.

What the old design teaches

Before the redesign, the tray had four native windows: the widget, its shadow, the home ball and the side badge. The handover of session V lists the main reason for its faults: "four windows that must look like one". The shadow, the ball and the widget show at the same time and must join without a gap.

The rule from this: split by what shows at the same time. The panel and the badge never show at the same time, and the dock has no object that flies from one to the other (spec: the panel folds into the ball, the ball pops out, then the badge slides in). So two windows for them do not have the "look like one" problem.

Short look

  • Vue <Transition>: six classes for enter and leave; Vue detects the end event itself.
  • Angular: animate.enter and animate.leave add CSS classes; it waits for the longest animation, with a 4 s fallback.
  • Framer Motion: AnimatePresence with exit and key; modes sync, wait, popLayout.
  • Adobe Spectrum: duration and ease tokens as CSS variables.
  • MudBlazor: no motion system; Duration and Delay are C# parameters, the same problem as ours. Blazor has no built-in transitions.
  • Page moves: none of these libraries has its own route transition API.

Closest to us

Web Awesome 3. It has CSS keyframes and tokens, one small JS helper that adds a class and waits for getAnimations(), and a state class from the host. Our orchMotion.settle is almost the same helper. Next are Radix and Headless UI: the state is in the framework, the motion is in CSS, and one presence part waits.
