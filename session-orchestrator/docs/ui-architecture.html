A new card

  1. LiveView.Load sees more cards. TrayStage.Notice runs.
  2. If the tray is hidden, the badge comes in (badge-out, then badge).
  3. The ring spins (.spin, 0.8 s). The peek bubble shows, and Peek(true) makes the click area wide.
  4. After 5 s (PeekTime, C#) the bubble goes. Then Peek(false).

How a motion is defined

  1. A token in motion.css :root: a time or a curve.
  2. A rule that uses the token, with the spec ID in a comment (M1 to M7, T1 to T4, N1, N2).
  3. A state class starts it: a phase (is-open), a Presence phase (is-leaving), a tab change (is-tab-in), a view transition (vt).
/* token */
--t-sheet-out: .22s;
/* rule: M5, a sheet leaves */
.is-leaving > .sheet { animation: m-down var(--t-sheet-out) ease-in both; }
/* state: Presence sets is-leaving, then waits (orchMotion.settle) */

Where the parts do not follow one flow

From this review of the code. Each one is a record in the issue tracker (I9 to I12). No fix is made.

I9 · Eight motion mechanisms no single flow

See the Motion paths tab. Two wait helpers do the same job with different rules: orchTray.end waits for one named property, orchMotion.settle waits for all animations. The deck has its own state machine in swipe.js.

I10 · Sizes in two places C# and CSS
C#  TrayWindow   ShadowMargin 24   TabRest 68   TabMargin 14   TabWide 280   BadgeWidth 332
CSS tray.css     inset: 24px       width: 68px  top: 14px      width: auto   (none)

The click area (C#) and the drawing (CSS) can disagree. I7 is one result.

I11 · Motion times outside the tokens literals in 4 files
  • app.css: deck .32 s, .45 s, .42 s, .3 s, .18 s; toggle .15 s.
  • swipe.js: 300, 180, 450, 60 ms. They must match app.css by hand.
  • motion.css: the undo bar is 5 s; Cards.UndoTime in C# is also 5 s.
  • TrayWindow: 300 ms hover fold; the token --t-badge-hover is 0.28 s.
  • TrayStage: the wait limits 900, 500, 1500, 400 ms.
I12 · Two wait rules for "the motion ended" different limits

orchTray.end: one element, one property name, a limit for each call. orchMotion.settle: a subtree, all finite animations, one limit token. A wrong property name in end waits for the full limit, with no error.
