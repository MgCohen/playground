Orchestrator setup options

How the orchestrator is installed and started on this PC, for one user. Each choice has a table. The pick of each table has a colored row.

Recommendation

Install published copies of the tray and the supervisor. The tray starts at login on the real store. If no supervisor answers on the port, the tray starts one in its own process. Update with one script.

Q1Run from source or install

OptionGoodBad
From source (dotnet run)Always the checkout code. No update stepBuild at each start. Locks bin/, so the next build fails. A branch switch changes the running app
Installed copy pickFast start. Stable while you work on branches. No DLL lockNeeds an update step after a merge

tray.ps1 stays for development: mock mode and the self-test.

Installed layout

%USERPROFILE%\Apps\Orchestrator\install root, one folder
tray\Orchestrator.Tray.exeone-file tray

The Startup and desktop shortcuts start it with --live <store> --hidden.

supervisor\Orchestrator.Web.dllpublished supervisor and UI

The tray starts it with ORCH_STORE and ORCH_PORT. It finds templates/ and config/ through the repository path that the build embeds.

install.jsoncommit, store, port

orch doctor reads it and compares the commit with the source.
