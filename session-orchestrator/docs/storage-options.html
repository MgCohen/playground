Session orchestrator · H1 storage

Orchestrator Storage Options

Decision: each store uses the VSA IRepository<T, TId>. Version 1 is a local folder implementation in %LOCALAPPDATA%\orch\store.

Version 2 is probably a Notion implementation: Notion is then the store, read through its API, with an in-memory cache for the life of the process.

A change of store is one new implementation and one changed line in the composition root. No caller changes.

All callers use repositories; only the implementations touch the storage

Four rules that each implementation must keep

  1. First write wins. SaveChangesAsync fails on an Add with an id that exists. Claims and the first answer use this.
  2. Version check. An entity has a version. A save of an old version fails. The cursor merge uses this.
  3. No IO outside the implementations. An architecture test fails on store file access in other code.
  4. One contract suite. The same NUnit tests run against each implementation.

Why Notion is the store and never a mirror

Notion linked database views keep related documents in sync. A change to one record shows in each page that points to it, with no extra updates. A mirror loses this, because the source of truth stays elsewhere.

H2 has no change of behavior: the local folder implementation takes the code of FileStore, EventStream and StreamWatcher. The existing tests must pass with no change.

Backup

  • Definitions (templates, policy defaults, mode presets) keep their source files in this repository. Git is their backup.
  • Instances (events, bodies, sessions, logs) get no backup now.

Rules for each part

  1. Change docs/store.md in the same commit as a store file.
  2. Keep each cache one that the store can make again.
  3. Test with a scratchpad ORCH_STORE, never with store/.

Non-goals

  • No Notion mirror. Reason: Notion is the store or is not used.
  • No configuration to select the implementation. Reason: one implementation at a time; a code change is enough.
  • No direct store access for cloud workers. Reason: one writer path keeps the lease and claim rules in C#.
  • No Notion calls in plugin hooks. Reason: the 10 s hook budget and the rate limit.
  • No migration of version 1 stores. Reason: store.md rule 4.
