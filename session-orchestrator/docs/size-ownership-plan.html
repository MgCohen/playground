Size ownership (R2): implementation and test plan

Six steps make the page the one owner of each tray size. The page lays out with CSS tokens, measures the shadow box of each part, and reports the boxes to C#. C# sets the window size and the click area from the report, and keeps only the work area, the saved places and the gap.

After R2, each size goes from the page to the window in one direction

Cause, from tray.css and BadgeWindow.cs

The window region is the click area, and Windows also clips the drawing to it. C# sets it from constants. The shadows of the tab and the peek bubble are larger than these constants.

StateShadow box (CSS px)Click area (CSS px)Cut
restx 251–332, y 11–105x 250–332, y 0–969 px at the bottom (I18)
hover, text 333 pxx −14–332, y 11–105x 38–332, y 0–9652 px at the left, ring cut (I7); 9 px bottom
peekbubble y about 17–99x 0–332, y 0–96about 3 px at the bubble bottom; 9 px at the tab

These values are calculations from the CSS shadows (--sh-raise: 0 10px 21px -8px gives 23 px below the tab). S0 measures them in the real page before any fix.

Terms

TermMeaning
Shadow boxThe border box of an element plus its outer shadows (offset + blur + spread), in CSS px of the window
Size reportThe boxes that the page measures and sends to C#: TraySizes
Click areaThe window region. It takes the clicks and clips the drawing
Badge staterest, hover or peek
Edge gapThe 12 px between the panel and the work area edge (C# Gap). Not the window gap of R1

The measure in the page

// tray.js: the shadow box = the border box + the outer shadows of the computed box-shadow.
function shadowBox(e) {
  var r = e.getBoundingClientRect(), b = { l: r.left, t: r.top, r: r.right, b: r.bottom };
  shadows(getComputedStyle(e).boxShadow).filter(s => !s.inset).forEach(s => {
    var g = s.blur + s.spread;
    b.l = Math.min(b.l, r.left + s.x - g); b.r = Math.max(b.r, r.right + s.x + g);
    b.t = Math.min(b.t, r.top + s.y - g);  b.b = Math.max(b.b, r.bottom + s.y + g);
  });
  return b;
}
// The hover box: the tab with width auto and no transition, measured and restored in one task (no paint between).

Each new check fails on the code before its step. If the check needs the code of its step, the fail-first proof is a change of one value: see FAIL, then restore it.

The shadow and ring check: badge-box-fits

For each badge state, the self-test measures the boxes with its own script, not with orchTray.sizes. So a defect in the product measure cannot hide a cut.

Q1 · Who owns the hover state of the badge (S3)?

The click area must stay wide until the fold ends. Today a 300 ms C# timer guesses the end. The R1 wait needs a step with a state class, but :hover is not a class.

OptionChangeEffect
AKeep :hover. The page waits with Settle on the tab, with no registry rowSmaller change. A wait outside the registry; the self-test hold needs a page seam too
BThe window sends the hover; the page sets is-hover; registry step badge-foldOne hover source for the click area and the look. On the R1 pipeline. The test hold uses the same path

Recommendation: B. The window already owns the hover for the click area, so one source cannot disagree.
