Devices plan: Android, web and desktop

Spike A1 shows that the Razor components run unchanged in an Android app. The plan makes one shared UI library, then three hosts on it: web, Windows tray and Android. Each phase has a check that shows it is done.

P1 · UI library · move only, no logic change
Goal
Each host references one library. No host links the files of another project.
Moves
Components/** except App.razor; Routes.razor; Board, Ui, Markdown, PageAct, PathTrail, ViewFilter, StreamHub, IWidgetWindow, NewSession; wwwroot assets.
Stays in Web
Program.cs, App.razor, Api/, SignIn, TickService.
Effect
The assets get the path _content/Orchestrator.Ui/. Each host page changes its links. Routes names the library assembly, so all hosts use one router.
Done when
dotnet test --solution Orchestrator.slnx passes. tray.ps1 -SelfTest passes. The web pages look the same.
Risk
bUnit tests and the tray self-test read asset paths. Change them in the same commit.
P2 · Shared mock and services · removes two copies
Goal
The tray and the Android app use the same demo data and the same service list.
Moves
MockStore, NoRunner, NoDocs from the tray to a small library Orchestrator.Demo.
Adds
One extension method in Orchestrator.Ui, for example AddOrchestratorUi(store, policy, ticks). It replaces the list in Tray/Program.cs and in the Android host.
Done when
Tray mock mode and live mode run. Tests pass.
P3 · Android host in src · the spike becomes a project
Goal
src/Orchestrator.Android references Orchestrator.Ui and Orchestrator.Demo, with no linked files.
Keeps from A1
Host page with autostart="false", SafeAreaEdges.All, templates as resources with ORCH_HOME.
Solution
A second solution file Orchestrator.Android.slnx. The main solution needs no Android workload.
Removes
spikes/android/.
Done when
The APK starts on the emulator and shows the home view.
P4 · Build and share · an APK on the phone in one step
Script
tools/android/build.ps1: install the user-local toolchain if missing, then build a release APK for android-arm64.
Signing
One release key. The key and its password stay in 1Password.
Size
Below 30 MB, so the file reaches the phone. Trim only if a test shows that it is safe.
Share
Open question: a GitHub release, or a file send.
Done when
The APK installs on the phone from the share link.
P5 · Android smoke test · the self-test for the phone
Script
tools/android/smoke.ps1: start the emulator, install, open each tab, swipe a card, take screenshots.
Output
A PASS list and the screens in docs/screens/android-*.png, as the tray self-test.
Done when
The script passes twice from a cold emulator.
P6 · Phone host features · small native parts
  • The Android back button goes back in the app. It must not close the app.
  • The status bar band has the theme color, not white.
  • The microphone: test speech.js in Android WebView. If it fails, add native speech through a host interface.
  • Optional: an Android notice for a new waiting card.

Non-goals

  • No change to the logic of the components. Reason: A1 shows that they work on Android as they are.
  • No backend work: no tunnel, no sign-in, no remote data. Reason: a separate plan covers the server.
  • No Play Store release. Reason: one user; an APK file is enough.
