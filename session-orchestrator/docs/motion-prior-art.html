Do design systems give a motion controller?

No. Design systems give components, tokens and motion guidance. Only Ionic on the web and the native SDKs give a motion controller, a navigation controller and a page model. Blazor has no native layer for it. A small layer of our own over the default Router (spike 07) gives the navigation part, and R1 drives the motion from its hooks.

Design systems stop at components and tokens. At most, they give one element-level animation component.

The controller layer is in frameworks and native SDKs: Ionic on the web, and UIKit, Jetpack and Flutter on native platforms.

Blazor has no native controller layer. The best shape is our own: the default Router, our PageHost in place of RouteView, and one Navigator service (spike 07). It passes all seven flows with no package. Bit.Brouter is the best library (Spikes tab).

Only Ionic, the native mobile SDKs and .NET MAUI cover all five layers

Yes: the library has the layer Part: one element, one helper or a spec No R1 builds it (motion tokens and the wait)

The family cells use the best member of the family. The Comparison tab gives the cell for each library, with a documentation link.

Recommendation

  1. Build the motion pipeline and the navigation controller. No library covers them for Blazor in two hosts.
  2. Copy the concepts of the What to copy tab. For the wait, use GSAP labels, Motion when and stagger, and WAAPI finished.
  3. For navigation, use the UIKit transition coordinator and the Flutter Navigator with typed results.
  4. Copy the React Aria FocusScope rules for overlays and sheets. Do not take a focus library.
  5. Use the Carbon or Material 3 token names as the model for motion.css. Add one reduced motion switch at the root.
  6. Optional: use IDialogService of Fluent UI Blazor only for simple dialogs. Do not use it as the page model.

Agent UI SDKs (A2UI, AI SDK, CopilotKit) give a component catalog and a data protocol. They give no motion controller and no navigation controller.

Fit checks against the R1 rules

Reduced motion. The report says "tokens go to 0 ms". R1 step S2 sets each duration token to 1 ms. Dwell tokens and limit tokens keep their values.

Offsets and ratios. An R1 registry row has only the step name and the state class (S4). C# has no token and no time. Thus a GSAP offset or a Flutter ratio is a token in motion.css, not a value in C#.

Exit-complete callback. R1 has no calls from JS to C#. C# waits for the result of MotionWait, then removes the element. That wait has the function of the callback.

Suggestions for us

  1. Keep the default Router and NavigationManager. Add only what Microsoft declined: the stack, keep-alive and page hooks (spike 07).
  2. Keep the motion.js wait for pipeline steps. It is the official "await a JS Promise" pattern.
  3. Use an official custom event only for a simple "tell this component when its animation ends" case. Give it a name that differs from the browser event (.NET 11 rule).
  4. Watch #10389 and #11212. If .NET 12 ships transitions, compare them with R1 before the change.

Our own shape is the best fit: spike 07. It keeps the default Router, replaces only RouteView with a PageHost, and adds one Navigator service. It passes all seven flows, with no package and 213 reusable lines.

Bit.Brouter is the best library. It gives the hooks, keep-alive and the push/pop mark, but no typed result and its own route table.

One move, from a click to the enter hook

click or Navigator callLocationChangingold: OnLeaveAsync (await, can cancel)Router finds page typePageHost: show kept slot + classwait 300 ms (R1: MotionWait)new: OnEnterAsync

A pushed page skips the URL part: PushAsync calls OnLeaveAsync, adds a slot to the stack, plays the move, and returns when the page calls CloseAsync.

Our app today uses the default navigation

The check is on the motion branch (orch/motion-review-fixes). We use each default feature that the refactorlogic.com guide shows, except NavigationLock and forceLoad.

Default featureWhere we use it
@page routesCards, Settings, Sessions, /events/{Id}, /sessions/{Id}
NavigationManager.NavigateToOpen.razor: Nav.NavigateTo("cards")
[SupplyParameterFromQuery]StreamPage.razor (Session)

IJSRuntime.InvokeAsyncThe JS command system wraps it and adds a trace, cancellation and a typed Result in place of an exception

motion.js does only what C# cannot do: wait for the end of CSS animations, start a view transition, and wait for the Blazor render. The JS confirm of the guide is a browser dialog; our guard is an in-page bar.

At scale

  • Keep-alive has a limit (KeepAliveMax) and ClearKeepAlive().

Opinion
It sets the routing only: the route table and an optional page interface. It does not touch state, components or style. Risks: version 11 is in preview, and the tray host (our own WebViewManager) is not tested.

// Navigator: typed push with a result
public async Task<TResult?> PushAsync<TPage, TResult>(IDictionary<string, object>? parameters = null)
{
    if (!await LeaveAsync(ctx)) return default;
    var slot = new PageSlot(typeof(TPage), parameters ?? new Dictionary<string, object>());
    stack.Add(slot);
    await host.PlayAsync(ctx);
    return await slot.Result.Task is TResult typed ? typed : default;
}
At scale
  • All default parts stay: @page with parameters, NotFound, server routes, prerender, links.
  • R1 plugs in at one place: PageHost.PlayAsync replaces Task.Delay with MotionWait.
  • Add a keep-alive limit and tab rules (the MASA model) to the Navigator.
Trap
A kept page does not render again by itself: the first run showed count = 0. The spike fixed it with a state subscription in the page. The better fix is a visit value that the host sends to all kept pages.
Open items
  • BackAsync with no history leaves the app (it calls history.back).
  • Two fast moves are not queued.
  • The browser does not say back or forward; the Navigator guesses from its visited list.
Opinion
The best fit. No package, no opinion outside navigation, and the API is the one we want: typed push, typed result, two hooks, one place for the motion. It is 213 reusable lines that we own and must test.

Recommendation

  1. Use the shape of spike 07: the default Router, our PageHost in <Found>, and one Navigator service.
  2. Let R1 do the motion in PageHost.PlayAsync, between OnLeaveAsync and OnEnterAsync.
  3. From 08, copy the state cascade, so kept pages render again on each visit. From MASA, copy tab rules plus a push stack.
  4. Keep Bit.Brouter as the library fallback. Do not take ReactiveUI, MASA or Ant Design for navigation.

What R1 is

R1 makes all motion of the tray one pipeline. Motion times are tokens in motion.css. One JS wait function has four modes: settle, property, time and event. A C# registry holds the motion steps and only their token names.

All visuals and motion are Razor and CSS. C# controls only the windows and the order of the steps. R1 has no calls from JS to C#.
