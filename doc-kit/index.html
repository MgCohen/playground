Doc Kit

Six blocks that our documents use, in one simple look. Each block is drawn by kit.js from a JSON file, with the real content of the artifact it came from. Under each block, a fold shows the shape of its data. The same shape is the target for the Notion mapping later.

  • 1Folder tree
  • 2Topology in columns
  • 3Topology graph
  • 4Call stacks
  • 5Folds
  • 6Composed folds
1

Folder tree

from Umpire Folder Layout

One line for each path. Folders open and close. Click a dotted description to see the details of that line.

2

Topology in columns

from VSA Split Map

One column for each group and one box for each part. Each group gets a color, and the size bar and the flag table use the same colors.

3

Topology graph

from Q6 Anchor and Host Types

Boxes in rows, arrows between them. The data gives a row and a column for each box. The kit calculates the positions and the arrows.

4

Call stacks

from Orchestrator Internals

A tree of calls. The kit draws the tree lines from the nesting, and puts each note in a column on the right. A wide stack becomes smaller until it fits.

5

Folds

from Unity Test Suite Map

Each fold has a title and a one-line summary. The body holds content blocks: text, code, lists, tables. Code in a fold becomes smaller until it fits.

6

Composed folds

from Umpire File Map

The same fold as block 5, with child folds. Each file has the same three child folds: Today, Proposal and Trade-offs.
